## Rule (FR-004)

`create_app` builds one `threading.Lock` per app and two wrapped initializers that share it:
`deps.create_all` (news storage, wraps the module-level `create_all` read when the app is built,
as now) and `deps.create_onboarding_tables` (wraps `Base.metadata.create_all(bind=onboarding_engine)`).
Each wrapper: take the lock; if its own done flag is set, return; call the initializer; set the
flag only after it returns. An exception propagates (the flag stays unset), so the handler's
existing `try` still answers 503 and the next request calls again. A new app instance starts with
both flags unset.
