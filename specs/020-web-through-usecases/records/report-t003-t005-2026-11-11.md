### How calls are counted

The fixture creates a temp SQLite database and its tables before installing spies, patches
`app.web.app.SessionLocal` to that database, then patches module-level `create_all` with the
news spy. The news spy holds the original bound metadata initializer, bypassing the onboarding
spy. `Base.metadata.create_all` is replaced with an onboarding spy before constructing the app;
the composition root and the old source handlers both resolve that same metadata object.
Thus setup and news DDL do not inflate the onboarding count, while onboarding calls execute
real DDL against the app's isolated engine unless the test supplies a failure/blocking effect.

The fixture intercepts `build_sources_router` without changing it, retaining the `WebDeps`
passed by `create_app`. Thread tests call those actual wrappers directly, with events holding
one initializer open and ensuring a second worker has started. Cross-initializer serialization
is tested in both directions. HTTP tests use `/api/news` and `/api/source-onboarding/latest`.
