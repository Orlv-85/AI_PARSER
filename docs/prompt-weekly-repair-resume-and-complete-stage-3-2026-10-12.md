## Выполнение

1. Исправь обработку operator-reviewed transport failure. Исходная попытка,
   ошибка, полный резерв, неизвестный actual usage и review provenance должны
   сохраняться. Reviewed failure не должен навсегда блокировать остальные задачи.
   Не удаляй failed row, не обнуляй резерв и не придумывай ответ провайдера.
2. Успешные ответы повторно не запрашивай. Для сбойного запроса допустима
   ограниченная новая попытка с отдельной записью, связью с исходной ошибкой и
   учётом обеих попыток; пользователь уже принял риск неопределённого расхода.
   Не превращай это в бесконечные retries. Если ответ получить не удалось,
   оставь материал явно unresolved, сохрани его в корректном учёте и продолжи
   остальные задачи. Financial review сам по себе не является semantic verdict.
3. Прежний frozen input не перезаписывай. Зафиксируй новую версию recovery-кода.
   Если проверка code hashes требует новой ревизии, выполни проверенный перенос
   с lineage и сохранением полного cumulative journal/cache. Старые артефакты
   сохрани; новую ревизию не используй как способ обнулить расходы или scope.
4. Добавь регрессии для reviewed transport failure, сохранения unknown expense,
   ограниченных retry attempts, отсутствия replay успешных ответов, отказа
   unreviewed/неоднозначного concurrent dispatch и корректного учёта unresolved.
   Выполни scoped checks, затем обязательный dev-quality-gate перед commit/push
   с изолированными БД. Обнови тот же PR #23, если он ещё открыт; при изменившемся
   состоянии Git сохрани работу и используй корректную отдельную fix-ветку.
5. После проверенного ремонта сразу возобнови расчёт из checkpoint. Обычные
   лимиты одной invocation преодолевай штатным resume с тем же lineage и кэшем.
   Сохраняй actual usage и неопределённые резервы автоматически. При новых
   временных сетевых сбоях используй проверенную ограниченную recovery-процедуру,
   а не новый цикл промптов на каждый запрос. Не обходи действующие денежные caps
   незаметным сбросом journal или созданием независимого бюджета.
6. Доведи до кандидатного English weekly report и проверь scope, counts,
   denominators, состояния тем, evidence, explanations и claim support.
   Coverage неизвестно: не выдумывай подтверждённые New/Up/Down, сохраняй
   наблюдаемые факты и предусмотренные quality/insufficient_evidence states.
