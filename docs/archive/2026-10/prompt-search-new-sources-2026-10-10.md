# Промпт для поиска новых источников

Прикрепи к чату файл `sources.yaml` и отправь следующий текст:

---

Найди 30 новых качественных источников для автоматического сборщика новостей об искусственном интеллекте. Используй поиск в интернете и проверяй найденные страницы. Если 30 подтверждённых источников найти не получится, верни меньше, без выдуманных ссылок.

Во вложении `sources.yaml` — актуальный снимок конфигурации из локального репозитория, а не подтверждённый реестр production. Перед отправкой приложи текущую версию файла. Прочитай весь YAML-список `sources`, включая записи с `enabled: false`, и раздел `defaults`: если поле не задано у источника, используй соответствующее значение по умолчанию. Все перечисленные источники уже известны: не предлагай их повторно. Файл не подтверждает полноту локального реестра БД или состав реестра на production.

Темы: новые модели и исследования, AI-агенты и автоматизация, AI-инструменты для разработки и тестирования ПО, практическое применение AI в компаниях, инфраструктура и оценка качества моделей. Предпочитай первичные источники: блоги разработчиков, лабораторий, компаний, университетов и журналы релизов. Допускаются качественные специализированные СМИ. Предпочтительные языки — английский и русский.

Требования:

1. Предпочитай официальные RSS/Atom. Если ленты нет, предложи HTML-страницу со списком публикаций или релизов. Сборщик поддерживает типы `rss` (включая Atom) и `html`.
2. Ссылка должна вести на регулярный поток публикаций, а не на отдельную статью, главную страницу продукта, страницу поиска или рекламный лендинг.
3. Для каждой ссылки проверь доступность без регистрации, фактическое содержание и дату последней публикации. Приоритет — источники с релевантными публикациями за последние 90 дней. Укажи дату проверки. HTTP 200 сам по себе не доказывает, что RSS работает: проверь XML и наличие элементов публикаций; для HTML проверь наличие списка статей.
4. Не выдумывай RSS-адреса, даты, результаты HTTP-проверок или CSS-селекторы. Если инструмент не позволяет проверить URL, вынеси его в `unverified`, а не в подтверждённые `sources`.
5. Исключи дубли с вложением и внутри результата. Сравнивай URL без фрагментов, трекинговых параметров и завершающего слеша, учитывай регистр хоста, редиректы, варианты http/https и www. Сохраняй значимые параметры запроса и регистр пути. Проверяй также название, владельца, переименования и содержание: RSS и HTML одной ленты — один источник. Разные разделы одного домена допустимы только при самостоятельном потоке публикаций и низком пересечении; объясни различие в `overlap_note`.
6. Отключённые источники из вложения не добавляй как новые. Если нашёл для известного источника рабочую замену URL, помести её отдельно в `replacement_suggestions`, с указанием существующего `id` и причины.
7. Не предлагай платные ленты, соцсети с обязательной авторизацией, зеркала или агрегаторы, которые в основном перепечатывают уже имеющиеся источники.

Верни результат как валидный JSON, без комментариев внутри JSON. Не смешивай новые источники с предложениями исправлений. Используй структуру:

```json
{
  "checked_at": "YYYY-MM-DD",
  "sources": [
    {
      "id": "unique_lowercase_id",
      "name": "Название источника",
      "type": "rss",
      "url": "https://publisher.example/feed.xml",
      "website_url": "https://publisher.example/blog",
      "language": "en",
      "topics": ["agents", "research"],
      "last_publication_date": "YYYY-MM-DD",
      "verification": {
        "method": "Как проверены доступность и формат",
        "evidence_url": "https://publisher.example/recent-article",
        "checked_at": "YYYY-MM-DD"
      },
      "why_add": "Чем источник полезен нашему сборщику",
      "overlap_note": "Почему не дублирует существующие источники"
    }
  ],
  "replacement_suggestions": [],
  "unverified": []
}
```

В `replacement_suggestions` используй поля `existing_id`, `old_url`, `suggested_url`, `type`, `reason`, `verification`. В `unverified` — `name`, `url`, `reason`.

JSON выше показывает только форму ответа; домен `publisher.example` — заглушка. `id` должен быть уникальным относительно вложения, длиной 2–64 символа, состоять только из `a-z`, цифр, `_` и `-`. Для неизвестной даты используй `null`. Для HTML можно добавить `html.list_selector` и `html.link_selector`, только если проверил их на фактическом HTML страницы. Дополнительные исследовательские поля будут обработаны отдельно перед импортом в конфигурацию.
