## 1. P2: подтверждённые неновостные HTML-страницы остаются в pending навсегда

Точка: `src/app/core/pipeline.py:1018`.

В HTML two-stage сначала создаётся pending placeholder. Затем
`fetch_html_article()` может вернуть `None` не только при ошибке разбора, но и
после положительного определения product landing или другого исключения:
`src/app/ingest/html.py:193`.

Сборщик считает любой `None` parser failure и оставляет placeholder pending.
На следующем цикле ledger воспроизводится до запроса списка. Поэтому уже
подтверждённый мусор повторно скачивается даже при HTTP 304 и после исчезновения
ссылки из списка. Повторяется сетевой запрос, а не платный запрос модели.

Offline-воспроизведение: `/products/ai-tool` с Features и Request a demo.
После двух циклов: два скачивания, ноль вызовов модели, один pending.

Исправление: отличать подтверждённое исключение от временной ошибки загрузки или
парсинга. Завершать placeholder только для подтверждённого исключения; временные
ошибки должны оставаться доступными для повтора. Не трактовать любой `None` как
окончательный отказ и не ослаблять предварительный фильтр.

## 2. P2: production Compose не передаёт новый флаг

Точки: `src/app/config/settings.py:48`, `docker-compose.prod.yml:41`.

Новая настройка читается из переменной `AINEWS_SEMANTIC_ADMISSION_ENABLED`, но её
нет в environment production-контейнера. Серверный `.env` служит для подстановок
Compose; он не примонтирован внутрь контейнера и не подключён через env_file.
Поэтому запись `AINEWS_SEMANTIC_ADMISSION_ENABLED=true` в серверный `.env` и
пересоздание app оставят функцию выключенной.

Исправление: добавить передачу флага с default false, не включая функцию на
production. Предусмотреть передачу версий policy/prompt, если оператор должен
управлять ими через тот же механизм. Добавить offline-проверку конфигурации и
уточнить документацию включения. Не изменять weekly, cron и текущий серверный .env.
