# Weekly report: этап 3 — рассчитать и проверить готовый отчёт

Прочитай `docs/weekly-report-stages-2026-10-12.md` и handoffs этапов 1/2. Выполни только этап 3 на зафиксированном входе и коде. Не начинай новый аудит корпуса.

1. Проверь input/code hashes, cache compatibility и полноту W0/W1/H. Перепроверь официальные тарифы, зафиксируй конечный scope, оценку и жёсткий общий бюджет с учётом уже сделанных calls этой ревизии. Используй согласованные ограничения; общее разрешение применять JEV/DeepSeek уже есть.
2. Запусти JEV weekly classification и bounded event checks; используй DeepSeek для предусмотренных неоднозначностей. Python считает deduplication, comparable cohort, метрики и состояния тем; DeepSeek объясняет уже вычисленные результаты по evidence. Анализ статей не перекладывай на Codex.
3. Работай через durable journal/cache, сохраняй usage каждого dispatch. При остановке продолжай существующую ревизию, не повторяя совместимые успешные запросы. Не обходи unknown-billing или budget safeguards.
4. Проверь итоговый payload, полноту входа, arithmetic, deduplication, source references, English explanations и claim support. Отсутствие подтверждённых карточек отдельной секции допускается с конкретной причиной; темы и ограниченные сигналы должны сохраняться в предусмотренном контрактом представлении. Не придумывай рост/спад/новизну и не меняй thresholds.
5. Сохрани готовую кандидатную ревизию и доказательства проверки приватно. Если обнаружен дефект кода, зафиксируй конкретное воспроизведение и оставь все оплаченные результаты для ремонта на этапе 2; не вноси незадокументированные изменения в код посреди расчёта.

Создай `docs/weekly-stage-3-result-2026-10-11.md`: путь/hash готового payload и входа, commit кода, число тем по состояниям, counts/coverage/exclusions, результаты проверки explanations, calls/tokens/cost, cache reuse и оставшиеся ограничения. Не раскрывай полный corpus или provider responses.

Этап завершён, когда кандидатный weekly report реально рассчитан, проверен и готов к штатной публикации без повторного анализа моделей. Не публикуй и не deploy на этом этапе. Остановись, дай пользователю краткий обзор полученных выводов и ссылку на промпт этапа 4.
